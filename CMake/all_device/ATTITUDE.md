# 姿态解算模块

`Core/Src/attitude_math.c` 与 `Core/Inc/attitude_math.h` 是独立数学模块，不依赖 HAL。
`device_app.c` 在每次 JY61P 完整成功采样后把数据交给它；原始读数仍保留。
此版本只增加姿态标定、换算和输出，没有接入 PID 或修改电机启动/PWM。


当前已按用户要求停用 RATE 的角速度零偏扣除：直接使用原始 GYRO 做安装坐标换算。
前10次角速度平均值仍保留在上下文中；不参与 RATE 或 FRONT/SIDE/YAW 的计算。

## 源码阅读顺序

先看 `device_app.c` 顶部的阅读路线与三个不同“状态”的解释，再按以下函数阅读：

1. `DevicesApp_Init()`：一次性设置应用初始状态，启动数学标定与深度请求。
2. `DevicesApp_Process()`：主循环总入口，各推进深度/姿态/串口一步。
3. `App_ProcessMotion()` 正常分支：等待启动、申请采样、取完整结果。
4. `App_UpdateAttitude()`：将原始数据交给数学模块，标记本次机体输出是否有效。
5. `attitude_math.c` 的 `Init -> Process -> FinishCalibration -> Solve`：10 次平均后建立矩阵，之后逐次解算。
6. `App_FormatAttitude()` 与三个 getter：只显示/读取已有结果，不推进标定。
7. 最后看每个文件标为“故障”的部分：失效标记、丢弃未完成平均、DMA/I2C/UART 清理。

应用读取状态机、底层 DMA 状态机、数学标定阶段互相独立。
源码中的“正常/故障”注释用于区分路径，不意味着本次修改了这些状态转换。

## 使用流程

1. 在启动前，把机器放在经过水平仪检查的水平支架上，保持静止直到出现 `BODY OK`。
2. 现有 1500 ms 稳定等待结束后，模块按至少 100 ms 间隔累计 10 次有效测量。
   JY61P 的实际更新率须至少为 10 Hz；若设置更低，需相应增大标定间隔。
   这里没有按照循环次数或串口打印次数计数，也不会因为数值相同就丢弃静止样本。
3. 对三个姿态角做环形平均，避免 ±180°边界处的算术平均错误；同时保留标定期间的角速度平均记录，当前不用于RATE扣除。
4. 根据水平 X/Y 倾角和已知的平面内安装朝向建立固定安装矩阵，然后设定相对初始航向。
5. 后续每次采样使用完整原始 X/Y/Z 角做矩阵换算，输出机体角度及转换后的向量。

不再根据角速度、加速度模长或角度波动自动清空标定：按间隔累计前 10 次有效采样。
机器是否水平静止由水平支架与操作保证；移动时也能完成累计，但得到的水平基准和角速度零偏会受影响。
非有限/超量程输入或通信故障仍会清掉未完成的标定；已有固定安装矩阵保留，最近一次姿态立即失效。
串口中的 `restart` 只统计这些无效输入/通信故障造成的未完成标定清空次数。

## 平面内安装方向

默认假设板子 +X 的水平投影指向机体右方、+Y 大致向前、+Z 大致向上。
单个水平姿态无法测出板子在机体水平面内装歪了多少。
如果这项偏角已由安装定位或已知姿态动作测出，修改 `device_app.c` 中
`SENSOR_X_HEADING_OFFSET_DEG`，表示板子 +X 水平投影相对机器右方的偏角，俯视逆时针为正。
默认值 0 并不意味着程序自动测出了这个偏角。

内部安装矩阵将传感器向量换到机体“右、前、上”坐标：

```
M = Rz(已知平面内安装偏角) Ry(平均原始Y) Rx(平均原始X)
H0 = 平均原始Z - 已知平面内安装偏角
R机体 = Rz(-H0) R传感器 transpose(M)
gyro机体 = M gyro传感器  // 当前已停用静止均值扣除
acc机体 = M acc传感器
```

输出角度按车辆常用的“前、左、上”坐标分解；为了方便操作，将俯仰符号改为抬头正。
这一步也处理了复合倾斜时右方轴航向与机头航向的区别。
归零只设置初始参考方向，不消除 JY61P 六轴航向的长期漂移。

## 串口和控制接口

原来的 `JY61P OK ... ANGLE(deg)=X,Y,Z` 是传感器原始数据，不改变其含义。
后面新增以下行：

```
BODY CAL n=4/10 restart=0
BODY OK t=... FRONT(deg)=... SIDE(deg)=... YAW(deg)=... RATE(deg/s)=... REF(deg)=... ACC_BODY(g)=...
```

- `FRONT`：机头抬高为正，范围 −90°～90°。
- `SIDE`：左侧抬高为正，范围 −180°～180°。
- `YAW`：机头向左转为正，相对本次标定时的机头朝向，范围 −180°～180°。
- `RATE`：绕机体右、前、上三根轴的角速度；对应抬头、左侧抬高、左转的正方向。
  这些角速度是机体角速度分量，不是三个欧拉角各自的变化率。
- `REF`：标定时平均的传感器原始 X/Y/Z 角，便于核对。
- `ACC_BODY`：安装补偿后的机体右、前、上三轴加速度，单位 g；保留重力对应读数。
  初始标定正确且机体水平静止时接近 `(0,0,+1) g`；抬头20°并静止时约 `(0,0.342,0.940) g`。
  原始 `JY61P` 行中的 `ACC(g)` 保留，方便对照；机体姿态无效时不输出旧的机体加速度。

未来 PID 从 `DevicesApp_GetAttitude()` 取机体数据，并检查返回值及采样时间戳。
标定未完成、通信故障、最近一次数学输入无效或机头竖直导致欧拉角分解不唯一时，返回 0。
需要重新标定时，在主循环调用 `DevicesApp_RestartAttitudeCalibration()`。
本版本每次启动重新标定，未写入 Flash，也未向 JY61P 发送硬件归零命令。

串口缓冲区扩大到 768 字节以容纳原始数据与机体结果；串口仍每秒输出一次。
深度采样流程保持原样。

## 验证

`tests/test_attitude_math.c` 使用四元数独立生成测试姿态，覆盖安装偏差、抬头/侧倾/
转向/复合动作、向量换算、角速度均值记录及RATE不扣均值、10样本间隔与平均、时钟回绕、航向 ±180°
边界、故障中断标定、非有限输入以及竖直机头的奇异姿态。
另重放导致旧版一直重启的用户日志，验证仍可在第 10 次有效采样完成标定且不因运动阈值重启。
该文件仅用于主机验证，不加入 STM32 固件。

上机时依次检查水平、抬头、左侧抬高、水平左转：对应的 `FRONT`、`SIDE`、`YAW`
应按上述方向变化。水平校正不能代替平面内安装方向验证。

本次验证结果：主机数值/状态测试全部通过；STM32F407 Debug 完整编译链接通过。
测试未连接或烧录机器，实际安装方向与传感器更新率仍需在实机确认。
